### Fixed

- **Health checks now appear in the request log** (#46). The scheduled health checks probed targets directly and never wrote a request log entry. Each probe is now logged with source `HEALTH_CHECK` and the `ClusterGate-HealthCheck/<version>` user agent. As before, the logs hide them unless the health-check filter is switched on.
- Analytics, route stats, the dashboard, recent errors and the traffic map leave health checks out, so the new entries don't change request counts, latency or error rates.

### Upgrade notes

- No configuration changes and no database migration. Pull the new images and redeploy.
- Every route with health checks enabled writes one log entry per check interval (5 minutes by default). Log retention cleans these up like any other entry.
