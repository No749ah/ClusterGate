### ⚠️ Breaking changes — read before upgrading

- **Route targets on localhost, the Kubernetes API and ClusterGate's own database are now blocked by default.** Loopback (`localhost`, `127.0.0.0/8`, `::1`, `0.0.0.0`), `kubernetes.default.svc…` / `KUBERNETES_SERVICE_HOST` and the `DATABASE_URL` host are rejected when a route is saved and again by the proxy on every connection (HTTP and WebSocket). Existing routes pointing there stop working. Set `TARGET_DENY_DEFAULTS=false` to restore the old behavior; `TARGET_DENY_EXTRA` adds your own entries. System admins can additionally restrict an organization's routes to an allowlist of namespaces and hosts (off by default).
- **Cookie-authenticated `/api` calls need a UI client token.** The UI receives an `X-CG-Client-Token` at login and keeps it in memory only; on a hard reload it re-obtains it by redirecting through `/api/auth/resume`, so expect one quick redirect. Scripts that call `/api` with only the session cookie now get `401`; use a bearer token instead (bearer-token clients are unaffected). `API_CLIENT_TOKEN_REQUIRED=false` turns the check off for debugging only.
- **Swagger "Try it out" needs a bearer token.** Authorize in Swagger UI with an API token; the browser session cookie alone is no longer accepted there.

### Other security changes

- ClusterGate's own `cg_*` cookies (session, CSRF) are no longer forwarded to upstream services, and upstream responses can no longer set them.
- Apps under `/r/` are isolated from the UI and API on the same host; the new per-route **Sandbox Pages** option serves untrusted apps from an opaque origin.
